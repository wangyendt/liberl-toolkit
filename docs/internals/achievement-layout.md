# Steam 构建 25721473 奖励成就适配

目标 EXE 的 SHA-256 与主程序 profile 相同。本模块不调用 Steam API，也不执行远程函数。

## 表格与阶段

读取用户的 `pac/steam/table_sc.pac` 内 `/t_achievement.tbl`：

- `AchievementCategoryData`：16 字节，uint64 分类 ID、uint64 分类文字偏移。
- `AchievementTableData`：96 字节，222 条。分类 ID / 成就 ID / objective / target 分别是 +0 / +4 / +8 / +12 的 uint32。
- 奖励是 +40 / +44 和 +52 / +56 的物品 ID / 数量 uint32 对；名称、说明的 UTF-8 偏移在 +72、+80。
- 无奖励的 CH 隐藏记录（ID 214）不属于用户可领取的 REWARD 条目；工具展示其余 221 条。
- `PlayRecordData` 为另一组记录，不当作奖励成就修改。

同一分类与 objective 的条目组成一组，按 target 排列。例如 objective 96 的编号顺序为 184、185、220、186、187，而目标依次为 10、50、150、250、400。递进不能按照 ID 大小推断。

## 状态和实际进度

每项状态占一个字节，容量 512：

| 字段 | 存档偏移 | 实时位置 |
|---|---|---|
| 成就状态 | `0x20B3A0 + ID` | `state + 0x20B3A8 + ID` |
| objective 统计 | `0x5100C + objective * 4` | `[module + 0xC61368] + 0x11100 + objective * 4` |

state 来自 `[module + 0xC61360]`。状态 bit 0 为完成，bit 1 为已领奖：0 未完成、1 可领奖、3 已领奖。拒绝异常状态，尤其是只有领奖位而缺少完成位的 2。

统计值使用带类型的 32 位数字：最高两位为类型，1 是低 30 位带符号整数；2 将整个 word 左移两位后视为 float，再截断为整数；其他类型由原生判定作 0 处理。非有限浮点数显示未知，不用于写入。战术奖励 objective 95 的阈值以十倍整数表示。

实时统计必须读取 system 对象；主状态对象对应 `0x5100C` 的位置只是缓存，实测存在旧值。统计只读，完成操作不改统计，也不补齐实际游戏行为。

## 原生证据和写入

- `0x23BC0` 起从 system + `0x11100 + objective*4` 读取计数，解析类型，与表格 +12 阈值比较。
- `0x23D52`：对 `state + ID + 0x20B3A8` OR 1，设置完成位。
- `0x131188` 起：读取相同状态字节，`flags & 3 == 1` 才进入奖励领取路径。
- `0x13179C`：OR 2，标记已领取奖励。工具不执行该路径，也不伪造奖品。

实时写入前检查两处完整指令字节，另外由 Editor 校验 EXE 哈希和主状态。只对选定条目（或明确勾选的较低阶段）的完成位做单字节写入。原存档自动备份，旧值和新值记入本地日志；系列修改作为一次可回滚、可撤销事务。领奖后状态从 1 变 3，撤销必须拒绝覆盖它。

测试包含原创合成表和存档，不分发游戏表、玩家存档、内存转储或原生反汇编输出。界面验证在存档副本中执行；实时只读验证确认 221 条状态、计数地址和领取判定指令。
